# v0.16 证据记忆索引成本对照（结果前冻结）

只优化应用层索引，CAS1与归档v1–v6不变；不发模型生成请求，不修改v0.15结果。
三策略同Zlib/64KiB CAS、相同完整来源树、相同提交标签和精确原字节：

| 策略 | 目的 |
|---|---|
| full-v1 | v0.15原始完整正文FTS索引，每快照一份，作为基线 |
| compact-full-v2 | contentless FTS5＋原记录定位表，每快照完整重建，隔离去正文副本的收益 |
| compact-delta-v2 | 相同紧凑基础索引，加不可变压缩定位增量，隔离快照复用的收益 |

新建库默认compact-delta-v2；已有v1库继续原策略，新增读取器兼容v1/v2应用清单。
v0.15读取器不支持新v2应用清单；旧归档/CAS读取兼容性独立验证。没有自动迁移或GC。

## 方法和边界

SQLite FTS5 content=''不保存title/body副本；定位表保存key、路径、字节范围、32B SHA
及记录类型。保留完整词位置、columnsize、porter unicode61、OR查询和全库BM25。
不将独立分片BM25分数合并。参考[SQLite官方文档](https://www.sqlite.org/fts5.html)。

初始不可变SQLite基础索引使用文件fsync后发布。增量记录删除key和新增/改变的原记录
定位，不复制正文；Zlib6压缩，清单绑定编码SHA、原长度、父/新CAS快照及基础索引SHA。
新快照仍全量读取/哈希来源、扫描记录，不宣称免除全量提交扫描。

有增量时，每次查询在内存中复制基础SQLite、从CAS读取必要的新/旧原记录并逐一SHA
校验，以FTS5 delete命令/insert重放。仅定位改变但原记录SHA不变时，更新定位；统计
不变。随后用SQLite的完整当前语料BM25排序，命中再按当前快照读取原文并校验。
每次搜索仍验证完整基础索引及全部增量SHA。临时内存、重放和CAS读取均计时。
不持久保存重建后的完整查询视图；无跨查询缓存，不靠跳过校验获得速度。

固定检查点规则：已有8层增量，或删除＋新/改变定位数量超过旧记录数25%（最少容许1条）
时，重建紧凑完整基础索引。位置大幅移动也计作改变。保留所有旧基础/增量/源字节，
不删历史来制造空间收益；相同来源不同标签可以复用视图。单写者、可信父目录；文件
同步不是目录/卷/真实掉电验证，发布失败的孤儿文件仍计费。

## 冻结实验

SciFact corpus.jsonl沿用既有SHA，5,183摘要、8,307,875B；claims_dev只在查询评分侧。
三策略各3轮，轮内种子20261019+round打乱策略执行顺序，每策略/轮独立进程和新库。
每阶段查询再起独立子进程，wall计Memory.search全过程，不含进程启动；另列进程总时
间与峰值RSS（含解释器、加载和查询），不是单条请求的内存增量。全部本机温缓存。

四阶段固定顺序：
1. original：原始语料，标签scifact-corpus-only；全部188条有证据主张，top10。
2. append：增加与v0.15机制测试相同的88B UTF-8/CRLF合成note；188条＋新增词项探针。
3. relocate：第一个摘要末尾加固定合成词，使后续JSON行偏移移动；前48条标注主张＋探针。
4. delete：删除合成note及第一个摘要；前48条标注主张＋探针。

relocate/delete是控制机制检查，人工修改后的资料不作科学质量提升主张。每阶段一次
不计正式次数的预热。首次索引创建/更新wall、CPU、全部保留逻辑文件字节分别记录。
原始文件、两次合成变化和原文恢复均逐字节核对；旧快照继续用original首48条主张
与探针重查。查询key顺序及原句/locator身份须与同轮full-v1完全一致；BM25绝对误差
<=1e-10。original的188条排名还对照v0.15已有检索记录。

原始阶段额外重建v0.15十二个有检索请求正文SHA，并用原模型响应验证引用；只是
离线输入/引用兼容核对，不产生新模型输出或推理质量结果。独立问题仍为188条，
重复轮次与控制探针不计入独立科学问题数。

空间账本计全部CAS对象/快照、基础/增量/配置、清单、HEAD和派生记录；本轮无模型
回答写入。另计整个memory_index.py专用源码一次。公共Python/SQLite/核心/操作系统
未全额分配，无完整部署净压缩承诺。与v0.15正式库含回答的35.73MB不直接算配对节省。

验收：全查询排序/来源一致、精确原字节和隔离检查通过，且相同阶段计专用源后文件
更小，才称本矩阵空间收益。延迟、峰值RSS和构建时间独立披露，不设事后速度门槛，
不把空间改善称全流程支配。没有新API、长会话、多跳、E3神经压缩或跨机器结论。
