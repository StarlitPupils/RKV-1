# v0.20 重放预算检查点（结果前冻结）

目标：复测v0.19的512变化读延迟退化，并分别验证记录字节和CAS解码放大，不能
只把25%调成另一比例后宣称解决。无模型API、原生新算法或跨查询缓存。

新profile=compact-budget-v3，物理清单/索引仍v3。新建库默认使用该策略，默认仍
固定64KiB。既有compact-base-v3保持原25%/256规则，明确选择后才改变未来写策略：
`memory-budget ROOT`原子替换writer配置，HEAD/已发布清单/历史视图不变。旧坏视图
不会因此变快；用已有相同源/相同label重用旧快照也不重建。旧v0.19能读新v3视图，
但不能用旧writer写新profile。旧writer失败可能留下未被HEAD引用的CAS对象。

新writer在25%累计非位置变化/256位移范围上限之外，增加三个默认预算：32个
removed+upserted；256KiB实际FTS重放原记录长度总和；2MiB预计CAS解码字节。
读取包括删除的旧记录、改写的旧和新记录、新增记录；raw SHA相同只改定位的分支
不读FTS文本。CAS字节按已验证快照引用和范围交集累计，每次读取触及整块均计费，
重复读同块重复收费，不以唯一块集合低估工作。估计不解码对象，不替代正式校验。
超限改为完整检查点，不拒绝提交，不删历史。因早退出，后续计量字段可为null。

这仅约束预定的重放工作量，不是wall/RSS硬上限。全索引SHA、SQLite复制/排序、
位移范围扫描、实际命中CAS读取等仍有成本。所有现有来源校验/全库BM25保留。
API可显式配置预算；字段/版本/整数及范围严格验证。默认值是工程起点，非全局最优。

同当前源码四个写策略：compact-full-v2全量重建、compact-base-v3旧策略、计数消融
（新profile、32变化/64MiB原记录/1GiB CAS宽字节限）、新默认三预算。无monkeypatch，
配置/诊断/源码成本都计。它比较策略，不是把整版v0.19/v0.20耗时直接相除。

四组纯合成控制，均先冻结再测，不称新增真实论文/科学问题：

* regression-gear：原样复用v0.19的2048记录、初始＋100更新和9查询阶段。source/
  label/Gear参数相同，旧策略与重建的每阶段持久树必须匹配v0.19记录（需同SQLite
  版本/可重现字节环境），以排除数据变更。该组是已见回归，非独立泛化样本。
* regression-fixed：相同源/更新，改用默认固定64KiB，验证当前默认分块组合。
* large-record：64记录，每个96KiB正文，Gear64KiB；初始、依次等长改3个标题、
  恢复初始源，共5状态。第2更新仅2个变化，应由原记录256KiB预算检查点。
* cas-amplification：4096小记录、固定1MiB块；同5状态，第1更新读旧/新块恰2MiB
  可重放，第2更新2记录的逐次解码4MiB超限，应因CAS预算检查点。它验证计数小且
  记录短仍可能解码放大；固定模式用Python，无原生扫描依赖。

新两控制是围绕独立预算的定向试验，非盲测；大记录/大块例子不能推导真实负载
占比。新默认第42更新应因变化数检查点，计数消融应同样解决该回归；在新两个
字节控制的第2更新，计数消融应保留overlay，新默认应分别触发record/CAS预算。
实际全部检查点位置和原因、阈值前/后查询与额外历史成本均保留，不只报最快状态。

四组四策略各三轮，新库/工作进程，20261024+round随机执行顺序及查询顺序。同轮
同组所有策略用同问题顺序。回归组沿用12词项和9阶段，新控制固定12词项、全5阶段。
每查询阶段新进程，一次排除统计预热；共336查询进程/预热、4032正式查询。每次
提交另在原始快照读4问题，共10176历史身份查询，以及2544次未来词项阴性探针。
所有2544已存快照结束后重开全源SHA/大小，当前源逐字节比较；这些含多轮多策略
重复实例，不是2544个独立数据版本。

query wall/CPU覆盖整个search调用与资源清理，进程启动另列；commit wall/CPU含
预算计量、建索引、源校验、HEAD发布。query RSS含整个新进程/输入。配对比值逐
同问题/同轮计算后取中位。与重建的key顺序、BM25绝对差<=1e-10、原文title/
sentences/完整locator身份必须一致，CAS同表示树相同，查询不改持久树。

整个RKV的全部Python源码及打包HTML资源计一次（含Store/core/CLI，未使用模块也
计入）；Gear两组加完整实测库和原native.json一次，固定两组无原生依赖。不重复
另计五个主要模块。Python/SQLite/OS、pyc、安装/文件系统元数据未全额分配，不称
完整部署净压缩。这与v0.19四模块口径不同，不直接计算版本压缩提升。精确旧扫描
库与CI新二进制身份分开核验。
仅本机温缓存，不测冷缓存/跨机器、掉电、并发写入、GC、长期对话、E3或模型质量。
