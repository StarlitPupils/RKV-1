# E2 CSV 配对试验（v0.4.0）

目的：扩大独立数值语料，诊断反变换成本，并检验一次不改变格式/校验的 Python
优化是否产生完整恢复与访问收益。按顺序接在 v0.3 多轮读取评测之后。

## 复现

```powershell
python -m pip install -e ".[zstd]"
python scripts/run_csv_trials.py --out results/local-csv
python scripts/summarize_csv.py results/local-csv
# 绘图另装 .[plots]
python scripts/summarize_csv.py results/local-csv --plot
```

输出目录必须不存在。Wine、HTRU2、Superconductivity 下载器固定 ZIP 和成员 SHA-256，
仅写选定原始文件，不改换行、数值原文或化学式，来源与许可记录在数据目录外。
32 MiB 下载上限、64 MiB ZIP 成员上限；不按 ZIP 的路径直接解压到文件系统。

## 假设与保留的负结果

- 原 CSV 反变换的逐单元 Python 索引/生成器构成可优化开销。
- 列切片 + zip 可减少该开销，但会增加引用存储，必须测恢复 RSS。
- 新语料上的类型变换可能无收益或不适用，必须保留 fallback 和全部容器成本。

HTRU2 原 CSV 为 CR-only；当前 CSV v1 明确只支持 LF/CRLF，不规范化为 LF 来制造
可压缩结果。Superconductivity 保留 train.csv 和含化学式的 unique_m.csv，后者
有不支持的混合单元，块可回退；不能只选择收益最高的文件代表整个数据集。

## 冻结基线与成本

`rkv1/experiments/csv_v0_3.py` 是 v0.3.0 的 transforms.py 原始 Git blob，SHA-256 为
`3a50f14a7e6998bf35fa475e2f0e8394e0c34912fade5baaa90c383cb7292ad6`。启动时核对快照。
基线只替换独立 worker 内的 CSV 反变换函数，其余读取器、压缩器、校验和 IO 使用
本版同一份实现；不是把整个历史应用速度与当前应用直接比较。

新反变换保留每项数字词法检查、维度/大小检查、换行 map 和最终块哈希。编码器
不改动，旧/新反变换读取同一份归档；普通模式另用 transform=none 对照。
所有 v0.4 条件共享相同源码部署，实验快照代码另记 runtime-footprint；它不写入
每个归档，也不能从完整部署成本中消失。源码指纹递归覆盖该实验子包。

## 执行与统计

三组输入 × Zlib 6/Zstd 3 × 普通/旧 CSV/新 CSV，共 18 个条件。固定 1 MiB、去重
开启，归档格式仍是 v2。每个 codec/transform 只编码一次并完整校验，不提出新的
编码速度结果。每条件一次完整恢复预热、五次正式恢复；恢复包括内部校验和文件
写入，随后在计时外逐字节比较整个目录。

每轮、每模式独立进程；常驻/重开两模式，每种可用类别 32 次正式查询、4 次预热。
同一轮的所有条件使用相同请求；完整归档预读后计时，只测本机温缓存。所有恢复、
读取配置/轮号/模式交错随机执行，保存执行顺序，避免所有基线总在新实现之前。

正式恢复报告五次中位数、范围、原始值；另按轮号比较旧/新比值与更快轮数。
读取报告五轮各自 nearest-rank p95 的中位数；32 请求的尾部估计较粗，不替代
v0.3 十轮/128 请求的读取矩阵。没有置信区间或显著性结论。

取一个实际变换块，对两个 decoder 各执行三次 cProfile，保存函数次数、自身和
累计时间；没有变换块时 profile=null。这是热点诊断，instrumentation 开销和
累计时间重叠使其不能作为纯性能实测或整目录 CPU 分解。

## 验证和边界

每个归档完整校验、每次完整恢复及范围读取逐字节比较，实验末尾核对归档、输入
和递归源码哈希。旧/新归档必须同 SHA-256，请求必须同指纹。最初格式和所有旧
归档保持兼容，默认 CSV 关闭；不会移除校验换取性能。

这里只验证数值 CSV 的局部实现优化；数组/代码/数学文本、Rust、神经编码、检索
和推理仍未开展。范围读取仍重建完整块，必须区分降低常数开销与真正块内访问。
冷缓存、跨机器、跨日和物理 IO 未测，不能由本轮 CPU 数据推断。
