# Receipt observability v0.96: fixed offline protocol

This opt-in experiment supplies a bounded plan/event inspector and owned process-fault fixtures. It does not resume the closed v095 campaign, reconstruct lost timing, execute missing tasks, read scientific corpora or call a provider. Default Memory/CLI/UI are unchanged.

The externally supplied plan SHA pins schema1, run_id, unique safe stages and automatic_replay=false. Event records require canonical JSON, exact keys, integer sequence (booleans rejected), previous-record SHA and ordered reserved/started/artifact_verified/stage_completed transitions. Artifacts require exact length/SHA. Limits are 64 stages,32KiB plan or witness,512KiB event log,1MiB per artifact; oversize reads stop at limit+1 and returned bytes count as application reads. Every append uses an exclusive writer lock, revalidates the prior log/artifacts, then appends/flushes/fsyncs. Failed writes/validation leave the lock and bytes; no stale-lock clearing or automatic continuation API. Inspection is read-only and never grants replay permission.

Overall completion requires all planned stage footers plus an externally anchored canonical parent witness binding run_id,planSHA,entireeventfileSHA,actualPID and actual observed integer exit0. Without that witness completion is unknown/false even if stage footers exist. Wrong-run/log/witnessSHA, boolean exit/byte counts, malformed/corrupt/truncated logs and stale locks refuse success. The caller must trust the parent observer and supply its external SHA: a local hash chain cannot authenticate its own controller. Path links/reparse points are refused. No malicious concurrent filesystem or power-loss guarantee.
