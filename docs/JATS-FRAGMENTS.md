# v0.24 原始JATS片段身份与重放预算预检（结果前冻结）

前置：v0.23的六篇eLife/18版本文件，固定输入清单与受控13状态时间线不变。
这次复用六篇，不增加独立论文/科学QA；已知各文件段落数来自正确性预检，尚未
测量片段变化/预算/成本。目的先验证更细记录是否值得集成，非新Memory索引格式。

## 实现合同

`rkv1.jats_fragments.fragments(raw, mode=...)` 返回原始连续XML字节范围，不重写XML。
父文章须满足既有eLife身份规则，UTF-8、<=1MiB，最多16384投影单元。记录标题、
普通摘要p及主body p；排除集合/嵌套p语义与整篇词法投影完全相同，空p也保留。
Expat事件的CurrentByteIndex定位原开闭标签，扫描标签末尾时尊重引号；自闭合
范围只含原标签，注释/CDATA/内联标签/实体的原始拼写保留。外部DTD不加载；内部
实体声明、外部实体引用、跳过的未解析实体全部拒绝，最后一项同时修复整篇读取。
参考Python官方事件/字节位置文档：
https://docs.python.org/3.13/library/pyexpat.html

每条包含key、parent_key、parent_sha256、role、selector、offset、length、sha256、
派生text。parent_sha256必须是完整原文件SHA，而非片段SHA；单独p通常没有父身份
或名称空间声明，不能把它称为独立完整XML。verify需读取/解析完整父文件，重算
全部描述后逐字段核对，返回原range。它是完整身份审计原语，不是有界range解码器。

两种规则均预定：position=父论文ID+title/abstract/body+各role的序号；xml-id优先
原元素id，否则同样回退序号。编码id避免键分隔冲突，投影元素id重复拒绝；序号键
明确表示位置，插入会造成键变化，不声称跨版语义稳定。id复用也不证明内容等价，
仍比较原range SHA及text。标题作为单独单元，不能复制到每段冒充原range证据。

## 确定性实验

1. 18文件×2规则，逐条verify原片段/父身份、全单元投影与整篇一致、连续非重叠。
   完整描述仅留本机，公开每文件数量、角色/id数、描述SHA/字节、定位元数据JSON
   （去text）字节、投影文本字节与覆盖原range总字节，不发布正文/原片段。
2. 固定64KiB/Python、Gear64KiB/精确旧实测Rust库，各生成独立CAS的13个状态；
   每状态全源逐字节检查，结束重开所有历史SHA/大小；全部历史保留，不GC。
3. 对每个相邻状态，用whole/position/xml-id记录，分别按v3原range SHA变化与v4
   投影相等重绑定规则规划。变更以相邻状态比较，是理想最短回放的必要条件；
   **不**模拟累积基础overlay，也不称实际检查点数或索引字节收益。保留原文件名，
   论文升级导致路径变化也须计元数据重绑定，不能偷偷改成固定文件名省操作。
4. 保留25%变化/256 relocation/4096 rebinding及32changes/256KiB记录/2MiB CAS
   门槛。只读range的工作量是未实现解码器的乐观下界；另按每次verify实际需读
   整个父文件计record/CAS字节，无跨记录缓存。两种分别报告，不用下界冒充实现。
   CAS计每range触及的完整raw块，重复触及照计；v4相同投影重绑定的父身份验证
   也必须计整父读取（下界方案可不读正文，只有可信基线/提交证明未来可实现）。
5. 每描述去text的canonical JSON全额计数，保留13状态的六文件上下文；这是简单
   未压缩元数据候选成本，非实际FTS/清单部署字节。不和v0.23完整系统体积算净省。

解析wall/CPU：18文件×whole/position/xml-id×3轮，打乱模式/文件顺序seed20261025+r；
每个条件一个新进程，预先加载固定输入，计只调用parser及输出描述，文件准备/
进程启动另列。每进程一次每文件，不人为循环到显著。RSS含进程/输入/结果，不
当增量内存。不测查询延迟/召回/科学QA；0API请求。确定性规划只跑一次，不为相同
预算计数重复制造样本。新模块/现有所有Python与HTML全额一次，Gear另外全DLL/
native.json，公共运行时未分配。解析时间与预算读字节不是最终端到端加速。

## 验收与解释

正确性不容差：所有原range SHA、父SHA、投影和历史恢复一致；篡改任何身份字段
拒绝；新旧整篇模式正常输入相同。失败则不能接入Memory。可行性不预设通过数：
报告每个转换/规则/v3-v4/分块/两种读模型的门槛原因。若range下界可过、完整父
验证不过，下一轮必须先设计可信父上下文与有界局部解码，并计资源，不能直接
上调预算或宣称段落索引已省空间/更快。若无优势则保留整篇默认。

版本0.24只添加独立审计API并拒绝遗漏实体；现有来源kind、Memory默认v3、显式
v4、CAS1、归档v1–v6与应用清单1–4保持。未改写已发布tag或原始输入。仅本机
温缓存、无新增科学质量/E3/多跳/长期对话/冷缓存/跨机器/掉电/GC结论。
