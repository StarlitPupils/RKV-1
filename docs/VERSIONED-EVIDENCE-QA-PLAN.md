# 带版本修订的证据问答对照设计

本方案承接 v0.100 完整交付后的主任务，依据 [开发与迭代指南](DEVELOPMENT-GUIDE.md) 制定。当前为协议草案，数据、评分材料和外部调用预算的冻结状态记录在 [决策清单](versioned-evidence-qa-plan.json)。本阶段交付物为任务定义、对照和决策规则。

## 使用问题与本轮范围

资料经过修订后，用户会问当前结论、过去某一版本的结论，或者要求处理互相冲突和不足的证据。首轮比较在相同来源、检索预算及回答条件下，RKV 能否保持有充分依据的正确回答比例，同时降低版本保存或更新的完整成本。质量测量也用于定位双方共同的证据和回答缺口。

本轮对照为简单版本归档和已发布 v0.100。先获得完整任务的基准，再根据实际失败环节选择一个改进。现有失败报告用于提出问题，后续正式评测材料按独立资料家族划分。

## 同等功能的两个系统

| 条件 | 简单对照 | RKV |
| --- | --- | --- |
| 保存资料 | 每个版本完整 Zstd 归档及原文 SHA256 清单 | 已发布的 Store、快照和原文校验 |
| 历史索引 | 每个版本单独建立 SQLite FTS5 索引 | 已发布默认 Memory 索引 |
| 版本选择 | 显式版本号，当前版本指针 | 显式 SID、当前版本或固定读视图 |
| 检索投影 | 共用同一个、预先冻结的文档投影及分词定义 | 相同投影及分词定义 |
| 排序与入证 | BM25、固定平局顺序、相同选句和预算 | 相同规则 |
| 回答与评分 | 共用同一提示、模型条件、输出格式和评分程序 | 相同条件 |

两组都实现版本读取、来源核验和清楚的错误返回。基线所需的索引、归档、历史资料、清单和依赖全部计费。RKV 的相关依赖按同样口径计费。基线实现先用自建资料验通，部署后的真实执行证据与开发目录行为分别保存。

检索规则相同的条件下，可能观察到完全相同的答案质量，同时保存或更新成本不同。这也是本轮需要报告的结果。首轮的质量门槛采用事先确定的容忍界限，成本改善为主要差异假设。未来确有新检索候选时，再定义该候选的质量改善假设。

## 资料与查询时间线

每个资料家族包含至少三个有来源依据的修订版本。保留原始文件和发布顺序，为每个版本记录原文、文件范围、时间及内容指纹。历史提问显式绑定目标版本，当前提问在请求开始时固定版本。时间戳提供版本顺序，具体答案仍根据可见证据判断。

每个测试家族预先定义六类查询实例，各一例。题目来源与标注方法须在正式材料冻结前确定。

| 实例 | 主要检查 |
| --- | --- |
| 初版当前问题 | 首次建库后能否找到充分依据并正确回答 |
| 修订后当前问题 | 资料发生有意义变化后，回答是否使用目标版本的内容 |
| 修订后历史追问 | 当前指针变化后，仍能回答明确指定的旧版本 |
| 再次修订后的跨文档问题 | 需要多处来源时，关键依据是否都实际进入回答上下文 |
| 同一目标版本内的冲突问题 | 两组适用范围相同的证据出现相反方向时，能否保留双方依据 |
| 证据不足问题 | 在事先定义并完整标注的有限证据范围内，能否识别无法确定结论 |

旧版与新版结论不同、研究对象不同、实验条件不同，均须按问题限定的版本和适用范围解释。冲突项要求标注说明双方为何适用于同一个待判断命题。证据不足项的标签只适用于声明的有限资料范围。

自然科学资料中若无法找到某类真实修订或冲突，不允许现场编造后计入科学样本。自建材料可覆盖同样的机制场景，单列机制结果。正式材料的纳入规则在检索和模型预测之前固定，发现标注缺陷时记录修订原因及影响范围。

## 数据隔离与评分

训练或开发资料与测试资料按论文、研究项目或修订家族整体分开，同一原文的修订版归入同一组。另记录全文、题目和近重复检查方法，以及整个数据家族此前在项目中的使用情况。模型训练数据是否包含公开资料保持未知。

测试题目、目标版本、参考答案和充分依据由可复核的标注流程形成。最低要求为两位独立标注者先给出标签和依据，再处理分歧并保存裁决。具体人员、材料许可、题目获得方式及盲法仍待确定。处理程序只读取问题和可见资料，全部预测落盘后才打开评分材料。

回答格式拟使用四类任务判定 `SUPPORTED`、`REFUTED`、`CONFLICTING`、`INSUFFICIENT`，另含来源引用和简短解释。现有三类回答校验器需要单独的评测适配层，两组共用。四类任务定义、冲突与否定的关系、引用数量和暴露范围检查均需用自建反例预检。

主要质量指标为 **目标版本正确、判定正确、关键依据充分且引用身份有效的回答比例**。充分依据可以有多个可接受集合，满足一个完整集合即可。冲突回答需要支持相反方向的适用证据。历史引用若正确绑定到错误版本，仍记为版本错误。标签和可接受依据集合在预测前封存。

同时报告各类题目的正确数、错误确信数、正确拒答数、格式失败、版本错误和全部缺失。题型的完整性与标注分歧分别列出。引用指纹检查和语义充分性各自评分。

## 配对、预算与成本

拟定两组配对运行。相同实例在两组中使用同一目标资料版本、相同提示和模型配置，顺序由输入身份的确定性规则交错生成。两组均先完成检索并持久化实际提供的上下文。外部回答调用前保存排他槽位预约，原始响应在本机保留，错误及缺失仍保留原分母。

开发和测试规模、top-k、原文入证预算、整个请求字节上限、输出 token 上限及超时均待冻结。现有接口的 top-k 5、正文 UTF-8 24,000 字节可作为预算候选。正文预算与整个请求大小分别校验。具体模型、版本标识、价格参考、调用次数和费用上限须有相应授权后写入正式清单。

成本分列一次建设、资料修订、单次查询与回答，以及历史研究投入。存储包括全部版本、索引、清单和模型相关资源。记录冷启动和热查询的作用域。模型调用、校验、失败、临时与孤立文件分别记账。全树 CPU/RSS、物理磁盘读写及远程运行资源未被可靠测量时保留未知。

相同输入上的方法差异按资料家族聚合，再做配对区间估计。统计方法和随机种子须预先固定。重复运行只用于运行波动，独立样本量以资料家族为基础。先明确最低有用改善，再评估可行样本量及统计功效。

## 决策与停止条件

正式冻结前必须确定质量容忍界限、最低有用的存储或更新成本改善，以及延迟、内存和费用上限。质量保持在容忍界限内且成本改善符合预定门槛时，才支持首轮的综合收益判断。未来质量候选另设最低有用质量改善。区间过宽时结论记为证据不足。

源码、全部输入及评分材料身份、纳入规则、预算和成功条件冻结，对应 CI 成功后，才进入唯一正式轮。失败后的新候选应重新提出机制假设和独立验证条件。

以下情况停止后续工作并保存原计划分母、已完成记录和未知项。

- 数据或源码身份不符、盲法被破坏、来源绑定失败。
- 外部请求出现连接、HTTP 或超时错误，或预算达到上限。
- 普通额度不可用、授权窗口结束或无法读取当前额度。
- 原始执行状态不足以确认可以安全发出下一次请求。

采用、限用、封存或证据不足的决定，应明确回到本方案的使用问题。外部调用名额按新方案独立授权，v0.89 和 v0.95 的封存轮次继续保留原状态。

## 正式冻结前的待办

1. 确定可用资料家族、真实修订及使用许可，先核对元数据，再决定数据访问范围。
2. 确定独立标注者和题目形成方法，并明确冲突及证据不足的有限范围。
3. 用自建资料实现并核验功能相当的基线和四类输出适配，覆盖版本错误和充分依据反例。
4. 确定最低有用改善、成本容忍界限、样本量和统计方法。
5. 在获准的模型、调用次数和费用范围内冻结执行清单与输入身份，再按开发指南推进。
