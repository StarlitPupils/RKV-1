# v0.18 查询内部资源复用与延后定位对照

先冻结实现、查询和协议，再进行正式测量。0次模型调用，不测新的推理质量。

假设：v0.17同一查询多次打开相同CAS快照，以及批量改写未变记录的定位，产生可避免
成本。完整基础索引SHA、overlay SHA、每个不同快照的规范/身份验证、每次CAS对象
stored/raw SHA和命中原记录SHA均保留。资源只活到一次search结束；没有跨查询缓存。

新实现复用请求内已经验证的快照/overlay。v3查询先验证全部位移范围的成员计数、
非负位置与无重复记录，仍完整删除/改写FTS词项、保持全库BM25，再只对命中且未被
upsert替换的定位换算偏移。不写持久索引，也不改变现有v1/v2/v3清单、CAS或归档格式。
构建时继续用原来的完整物化视图验证；累计变更/区间检查点门槛不变。

诊断cProfile与正式无剖析器耗时分开。profile-before/after覆盖原始、追加、13B插入、
删除首记录及最终5阶段，仅作热点分析。正式测量只使用冻结后的实现。

三条件：实际v0.17已发布wheel中的46个原样Python模块；新实现强制完整定位重放
（scoped-eager，实验包装器消融）；新实现默认延后定位（scoped-deferred）。
消融只在基准进程包装view，不是产品选项。两项优化的联合收益与各自增量分别报告。

读取v0.17固定/v3和Gear/v3两组现有持久文件，全部历史保留，每组11快照。来源是
原始SciFact 5,183摘要及v0.17预定合成更新，不代表新的真实版本家族。优先复用
`scripts.run_memory_updates`生成的0-fixed-v3和0-gear-rust-v3及相邻trial JSON；
Gear数据与Python扫描逐字节相同，查询不加载原生扫描库。

测量阶段固定为0/1/3/9/10（原始、追加、短插入、删首记录、最终）。每阶段查询全部
188条标注主张及3个旧探针，共191条，不再只测更新后的前32条。三轮、每轮条件/
表示/阶段顺序及查询顺序按20261021+round打乱，同轮查询顺序相同。每个组合新进程，
一次明确预热，之后每次search仍重新执行全部规定验证与重放。共90进程、90预热、
17,190次正式查询；独立主张仍188，探针/重复轮次不增加科学样本量。

每个查询记录整个search调用wall/CPU、内部报告wall、key顺序、BM25、题目SHA、原
title/sentences/完整locator身份摘要。绝对BM25误差<=1e-10，结果必须匹配同轮/同表示/
同阶段v0.17。不同表示snapshot_id可以不同，不以跨表示ID相等作为验收门槛。
耗时含校验/视图/定位/命中原文读取和请求资源清理，不含进程启动；进程总时长另列。
报告逐问题/轮配对比值中位、总体中位/p95；RSS是整个查询进程峰值而非单请求增量。

每组11个历史快照结束后全部重开核对当时全源SHA/大小。两组持久树的每个文件大小/
SHA在正式测量前后完全一致，不只比较总字节。查询不测提交加速或新压缩比。

两种发行实现各计memory.py和memory_index.py整份源一次；共享框架/解释器/SQLite/
OS及文件系统元数据未全额分配。实测查询不加载DLL，不沿用v0.17扫描DLL计费。
源码增加、持久文件不变、运行时RSS分别列出，不把减少重放成本称为索引压缩收益。
本机温缓存；冷缓存、跨机器、并发写入、真实掉电、长期会话、多跳、E3、模型质量未测。
