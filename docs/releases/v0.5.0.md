# 独立校验单元与完整索引成本

整块 CSV 范围读取需恢复大块，直接改成小块又扩大 JSON 清单、增加每次打开成本。
本版可选 RKV v3：1 MiB 父块内的16/64KiB单元独立压缩、反变换并验证原始 SHA-256，
二进制索引按需校验/缓存；完整恢复继续验证父块和文件。默认仍写 v2，CSV 默认关闭。

- 新增 --unit-size、固定48字节单元条目、索引校验链和有预算的 LRU 索引缓存。
- 读取器支持 v1/v2/v3；不指定单元的 v2 字节与 v0.4 固定 fixture 一致。旧读取器不读 v3。
- 范围返回触及单元的校验结果；未触及损坏可能不影响局部读，完整 verify 必須失败。
- 全部索引、摘要、标志、JSON、prefix/payload计入总大小；不重复计费索引。
- 对照整块、直接16/64KiB小块、两层16/64KiB单元、普通编码和无索引缓存。
- 实验/格式文档、原始请求、源码/输入哈希、逐轮数据、图形和复现脚本随版本保存。
- 根据已有 CSV 热点实现 Rust C ABI 候选，CI 在 Windows/Linux 比较8个 Python 表格；
  平台库 ZIP 附 ABI/编译器/源提交/二进制 SHA-256。本轮没有原生性能数据。

## 验证与结果

四组输入、53条件；265次正式完整恢复与53次预热恢复、101,760次正式范围读取及
6,360次查询预热全部逐字节一致。每条件五次编码/恢复；每轮每类别64次匹配查询。
本地56项测试：55通过、1因Windows符号链接权限跳过；发布前CI再运行跨平台Python、
Rust和原生差分验证。归档确定性、输入/源码/归档不变与索引计费均核对。

Zstd、温缓存，各轮重开 p95 的中位数：

| 数据 / 变换 | 布局 | 总 bytes | 重开 p95 ms |
|---|---|---:|---:|
| 超导材料 / CSV | 整块1MiB | 7,442,705 | 30.921 |
| 超导材料 / CSV | 直接16KiB | 8,761,101 | 13.645 |
| 超导材料 / CSV | 两层16KiB | 8,423,479 | 1.378 |
| QASPER / none | 整块1MiB | 10,660,769 | 2.221 |
| QASPER / none | 直接64KiB | 12,415,158 | 5.208 |
| QASPER / none | 两层64KiB | 12,299,774 | 0.870 |

两层16KiB的超导材料CSV比同尺寸直接小块节省3.85%，配对重开p95加速中位9.75倍；
QASPER两层64KiB相应节省0.93%、加速5.95倍，均五轮更快。相对1MiB整块的体积
仍增大；常驻读取和完整恢复不是全面改善。超导材料普通Zstd/两层64KiB的重开
约0.703ms，比相同CSV的2.463ms更快；默认策略不据此自动替换。

## 成本、范围与下一步

单机温缓存、五轮描述统计；不声称显著性、全局最优或科学推理收益。逻辑解码放大
按单元计算，不等于物理IO；范围RSS含工作账本读取器/真值，恢复RSS单独测。缓存
预算是实现计费估算，不是硬RSS限制；只缓存索引，不缓存解码内容。

Rust候选不负责codec或哈希，本轮所有性能实验仍为Python；下一步在同归档下测
Python/原生并计二进制资源成本，再开展真实版本序列、CDC与共享块存储。当前父块
仍是去重/增量复用粒度，未实现跨父块单元CAS、追加式版本存储。数组/代码/数学文本、
E3/E4仍待开展。冷缓存/跨机器按用户选择明确未测，旧Release/tag与结果不覆盖。
