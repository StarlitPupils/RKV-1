# 热点剖析与精确 Rust Gear 边界扫描

共享Gear在真实版本序列上节省存储，但Python逐字节循环拖慢提交。本版先对冻结
v0.7源码做诊断，再只迁移该边界扫描到Rust。表、u64递推、单mask/min/max、跨缓冲区
状态及残余字节保持一致；Python仍组装原文、执行哈希/压缩/旧对象验证/fsync/发布。

- 显式`store-add --chunker-backend rust --native-library ...`及同名API参数；默认Python。
  Gear独立ABI=1，与CSV ABI=1并存。元数据/库摘要/编译来源检查保留，Gear不支持的
  元数据在加载DLL前拒绝。CAS format version=1及旧RKV v1/v2/v3均不改变。
- 冻结v0.7源码指纹与诊断、迁移后诊断分开记录；cProfile会扰动逐字节调用成本，
  只作定位，主实验不带剖析器。新增六条件五轮匹配，所有后端存储树和对象账本一致。
- 保留全部对象头/摘要/快照/config/未引用对象成本，整份DLL+元数据另计一次。
  不以库内Gear符号大小冒充额外资源，也不宣称完整物理卷或公共运行时成本。

## 验证与实验结果

QASPER官方原始train/dev v0.1→v0.2→v0.3，128,076,252原文字节，全部Zstd3、无CSV/模型。
正式 **90次完整恢复、34,560次范围读取**，另18次恢复预热、2,160次查询预热全部
逐字节一致。实际请求指纹、源码/输入/库/元数据/读取前后存储树均核对；全部主实验
存储树与v0.7已发表的同表示字节相同。本机75项测试：74通过、1符号链接权限跳过。
源提交`96be8d0361407d6970bcb1101e2770151951483d`的Windows/Linux、Python3.10/3.13、
Rust/native差分及损坏/复用检查通过；最终tag发布同样要求CI通过。

共享Gear三版提交中位 **28.989→2.971秒**，同轮配对加速中位 **9.88倍**，5/5轮更快；
独立Gear **28.833→2.779秒**，配对加速 **10.54倍**，5/5轮更快。配对中位与两个
耗时中位之比不同，不用历史v0.7耗时推算加速。
共享逐轮配对范围8.15–16.66倍、原生三版提交wall范围1.70–3.56秒，波动保留，
不将其作为置信区间或统计显著性证据。

共享Gear存储仍为 **23,946,864 bytes**，914个文件。冻结DLL123,904bytes、元数据515bytes，
整份库成本124,419bytes；合计 **24,071,283 bytes**，比旧独立1MiB RKV的31,519,475bytes
少 **23.63%**。提交仍为本轮旧RKV0.623秒的 **4.77倍**；完整恢复0.517/0.260秒，
重开p95 3.793/2.233ms。恢复和读取没有迁移Rust，不能将其波动当作原生解码加速。

## 使用与复现

格式/CLI见docs/STORE.md；ABI与实验见docs/NATIVE.md。
`python -m scripts.run_gear --native-library <frozen DLL> --out results/local-gear`
生成新报告；摘要用`python -m scripts.summarize_gear results/local-gear`生成。

使用额外资产 **rkv1-native-measured-v0.8.0-windows-x86_64.zip** 重现本机时序，保留其中
原始native.json。它保存源CI的实测二进制，DLL SHA-256为
`7736879b67377038fdc2211fbdadfc12c71983ba96257dbb8a18c33c660196e2`。
一般Windows/Linux新构建资产记录自身身份，不能假定与实测库逐字节相同。
原始配对样本、独立验证脚本、指纹、剖析、资源成本与科学图均在results/v0.8.0。

所有源仍全量扫描，复用仍验证旧对象。简单Gear不是FastCDC，64KiB为mask scale，
平均约87.4KiB。底层一对象一文件；剩余诊断热点为发布/压缩及旧对象验证。
无GC、无断电耐久性证明；仅一个家族三版、本机温缓存五轮，不做显著性或普遍最优
结论。冷缓存、跨机器、跨日、神经预测和科学推理质量未测。下一步评估对象发布/
访问成本、扩大独立真实版本家族与E2类型。历史tag/实验记录不改写。
