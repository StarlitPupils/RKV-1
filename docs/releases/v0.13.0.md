# 归档恢复文件同步、故障边界与历史账本更正

归档unpack默认在完整文件SHA验证后flush→fsync→close（含空文件），全部完成后
发布目录。显式--sync-policy close保留历史关闭边界；同步失败直接报错，不降级。
verify不写文件；CAS恢复保持既有实现。编码/格式v1–v6不变，不宣称压缩率改善。

同归档、十轮配对的80次正式恢复与8次预热全逐字节一致，正式完成1,350次文件
fsync请求。close/files恢复中位ms：ECG v4 7.038/22.231；M13 v4 29.660/87.844；
M13 v6 27.365/88.260；130文件合成对照40.273/553.017。逐轮files/close配对中位
分别3.135×、3.003×、3.257×、13.716×，配对额外15.298/58.733/61.207/512.846ms。
这些是温缓存本机完整恢复观测，含发布重试等待，不是纯fsync内核延迟或跨设备结论。

v1–v6×11情形×3轮的198条审计全符合预期：写、flush、fsync、关闭或发布前失败
不发布；发布前强杀留下私有暂存，目标不存在；发布后强杀目标完整存在但可能没有
成功返回。没有自动孤儿恢复、目录/卷同步、真实掉电或多写者事务保证。

首轮在close路径遇Windows目录rename拒绝，本地化错误还暴露子进程诊断解码问题；
中止记录/已丢失的逐job时序范围如实保留，未计入最终样本。修订版强制UTF-8；
仅Windows rename 5/32/33错误最多4次尝试，等待10/50/100ms计时，不修改ACL、
不复制回退、不重试fsync或整次恢复。最终正式样本发布重试1次、失败0；所有job保留。

v0.12工作量更正：分段范围读的分析账本误用固定偏移。本版改为真实前缀定位，
全部100归档重编码完整SHA/存储账本一致，96,000次原请求经独立线性扫描核对。
24个分段配置、720组工作量账本需更正；固定布局不变。旧标签/结果不覆盖，原延迟
未重测，归档成本与0/8联合验收计算不变。

本机115项测试：114通过、1Windows符号链接权限跳过。冻结源候选Windows/Linux CI
通过；标签发布由CI重新测试。专用persistence.py源1,252B，无新增DLL/模型/字典；
公共Python/core/codec不完全分配，不称完整部署大小。原生发行包仍只提供CSV/Gear，
不用于本次同步计时。冷缓存、跨机器性能、数值Rust、E3/E4和推理收益未测。
