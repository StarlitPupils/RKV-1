# 同格式对象 IO 消融与第二个真实版本家族

v0.8 迁移 Gear 扫描后，对象访问与发布成为剩余成本。本版实现两个显式候选并做
消融：`--io-backend bounded` 减少重复目录/长度查询、用有界读取验证精确 EOF；
Windows `--publisher rename` 使用不覆盖目标的同目录重命名。每个新文件仍
flush/fsync，旧对象仍完整校验。CAS format=1、旧 RKV v1/v2/v3 均不改变。

**候选没有证明稳定、全面提速，默认仍 reference/link；Gear 默认仍 Python。**
本版包含负结果，未将候选提升为默认。没有新增原生 IO 或 CAS 解码器。

## 实验与判断

QASPER 三个原始发布，加 Evidence Inference v1.2/v1.3/v1.4 的两张原始主 CSV 表，
合计146,823,495原文字节。每家族八条件、五轮；全部 Zstd3，无 CSV 变换/模型。
冻结 v0.8 Store 的源码字节与旧 tag 完全相同，另设当前 reference 控制；全部 Gear
使用同一冻结 Rust 扫描库。输入、源码、库、元数据前后指纹与实际查询计划均核对。

**240 次正式完整恢复、92,160 次正式范围读取**，另48次恢复预热、5,760次查询预热
全部逐字节一致。同表示所有 IO 策略的完整存储树、快照和对象账本相同，QASPER
树字节也与 v0.8 相同。本机82项测试：81通过、1 Windows符号链接权限跳过。
Windows/Linux、Python3.10/3.13、Rust/native 的候选 CI 已通过，tag 发布也以 CI 为门槛。

| 三版指标 | QASPER | Evidence Inference 两表 |
|---|---:|---:|
| 独立1MiB归档 bytes | 31,519,475 | 3,760,981 |
| 共享Gear CAS bytes | 23,946,864 | 2,608,262 |
| 加整份实测库 bytes | 24,071,283 | 2,732,681 |
| 含库对独立归档节省 | 23.63% | 27.34% |
| reference提交中位 s | 2.397 | 0.223 |

| 组合提交配对加速中位 | 0.974×，2/5轮更快 | 1.026×，4/5轮更快 |

配对倍率先逐轮相除，再取中位，不等同于两个耗时中位之比。组合逐轮范围分别
0.854–1.466×、0.976–1.584×，均跨过1。单独 bounded 提交为0.889×/0.766×，
单独 rename 为0.760×/0.929×。bounded 常驻范围p95为1.103×/1.081×，重开为
0.991×/1.036×，完整恢复为1.008×/1.034×。这是温缓存描述统计，无显著性结论。
rename不改变读取实现，不能将它的读取波动当作解码加速。

Evidence 两表共享 Gear 相对同格式独立 Gear 减少40.32%逻辑字节；其中 prompts
三版完全相同，约17.9%原文整文件不变。原始路径、字节、换行和 SHA 固定；未测
论文全文、附加表或医学推理。共享 Gear 三版提交0.214秒仍慢于独立归档0.083秒。
QASPER组合提交2.124秒也仍慢于独立归档0.671秒，存储与速度继续存在取舍。

## 资产、兼容与复现

详见仓库 `docs/IO.md`、`results/v0.9.0/SUMMARY.md`、两家族原始 JSON、逐轮配对、
独立验证、源码指纹和带五轮观测点的科学图。

```powershell
python -m scripts.run_io --native-library native/rkv1_core.dll --out results/local-io
python -m scripts.summarize_io results/local-io
```

解压附加资产 `rkv1-native-measured-v0.9.0-windows-x86_64.zip` 到 `native/`，保留原始
`native.json`。其中 DLL SHA-256：
`7736879b67377038fdc2211fbdadfc12c71983ba96257dbb8a18c33c660196e2`。
它逐字节复用 v0.8 实测库，源提交
`96be8d0361407d6970bcb1101e2770151951483d`，DLL123,904bytes、元数据515bytes，合计
124,419bytes。通用 Windows/Linux 新构建包记录自身身份，不能假定与实测库相同。
每家族单独部署全额计一次，两个独立仓库共用一份库则合计26,679,545bytes，比
各自独立归档之和少24.38%；这是资源摊销情景，没有跨家族去重实验。

包验证记录中的 wheel SHA 属于本地 Windows 构建；CI 发布容器的 SHA 独立记录，
两者所有实测 Python 源字节必须相同。候选生成的 CAS 由已发布 v0.7 读取器恢复；
损坏/尾部、并发不覆盖、同步失败、快照失败和旧格式 fixture 均有验证。

逻辑成本包括对象头/双摘要/payload、配置、快照和未引用对象；文件数据分配另记。
目录/MFT/日志/公共 Python 和 codec 未全额分配，不称为完整物理或部署成本。
仍无GC与断电耐久性证明。冷缓存、跨机器、跨日和推理质量明确未测。
下一优先项转向 E2 数组/数值类型的完整成本对照；E3/E4 尚未实测。历史 tag 不改写。
