# 多轮读取与读取器生命周期评测

单批范围查询无法判断配置排序是否稳定，也没有直接记录清单打开阶段。本版新增
多种子、交错执行的读取协议，分别测常驻读取器和每请求重新打开，并分开记录
打开/读取/关闭耗时。沿用 RKV v2 格式、压缩核心和默认参数，旧归档继续可读。

- 新增 bench-reads CLI、run_reading.py 和 summarize_reading.py，默认拒绝覆盖旧记录。
- SciFact/QASPER × raw/Zlib 6/Zstd 3 × 64 KiB/256 KiB/1 MiB，共 18 配置。
- 每配置两个连续批次、每批五个查询种子；每种可用类别 128 次正式请求、8 次预热。
- 非跨块请求在 codec、块大小、模式之间完全配对；每轮/模式独立进程，执行顺序交错打乱。
- 保存实际请求、指纹、原始延迟、阶段跨度、逐轮 p95、源码/输入哈希和逻辑解码放大。

## 验证与结果

360 个独立 worker，161,280 次正式范围读取和 10,080 次预热读取全部逐字节一致。
18 个归档先完整校验；归档哈希与 v0.2 对应条件相同，实验前后输入与实现指纹一致。
本地 38 项测试中 37 通过，1 因 Windows 符号链接权限跳过；发布前 CI 运行跨平台
Python/Zstd 测试和 Rust 骨架测试。图形和汇总可从原始 JSON 重建。

Zstd 加权请求，十轮各自 p95 的中位数（ms）：

| 数据 | 块 KiB | 常驻读取器 | 每次重新打开 |
|---|---:|---:|---:|
| SciFact | 64 | 0.177 | 1.465 |
| SciFact | 256 | 0.442 | 1.027 |
| SciFact | 1024 | 1.749 | 2.140 |
| QASPER | 64 | 0.152 | 5.298 |
| QASPER | 256 | 0.413 | 2.014 |
| QASPER | 1024 | 1.623 | 2.321 |

常驻时 64 KiB 在两组所有十轮都快于 1 MiB，但归档分别增大 14.41%/16.46%。
重开时 256 KiB 对 SciFact 十轮全胜，对 QASPER 九轮胜过 1 MiB。QASPER 64 KiB
的打开阶段中位约 4.658 ms，清单成本使小块排序反转；不是只测 JSON 解析。
默认配置保持不变，不能从这两组工作负载推断通用最优。

## 边界与下一步

按用户选择，只完成当前本机温缓存评测。每个 worker 计时前预读完整归档；独立
进程或重新打开不代表冷磁盘。冷缓存、跨机器、跨日、成熟 seekable 系统和推理
质量保持 null。两个批次连续执行，后台负载和 CPU 频率未隔离。

图中范围是十轮 p95 的最小/最大值，不是置信区间。逻辑触及字节不代表物理 IO；
内存含预先准备的查询真值，不能直接与旧版完整恢复 RSS 比较。此次改的是评测
协议，不将两版延迟差归为存储核心加速。

下一步按顺序推进 E2：扩大独立数值数据、分析反变换与块内访问热点，再决定 Rust
迁移；之后验证真实版本序列和共享块存储。E3/E4 仍未开展。附件包含 wheel、源码
包和完整实验记录 ZIP；旧 Release/tag 不覆盖。
