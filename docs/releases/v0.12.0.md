# FITS 类型分流、区域分块与预定验收

E2新增编码侧FITS白名单：只识别一个完整2D float32/64主图像，头/图像/填充按原始
边界分块，仅对图像字节按BITPIX选4/8字节重排。固定块类型策略只处理完全位于图像
内部的块。全文件原字节、文件名、NaN payload与填充恢复不变，不转换数值/端序。
未知或不支持格式回退普通编码；不是ECG通道布局或通用类型识别。

## v6与兼容

新v6顶层layout=fixed/fits-segments-v1；分段布局允许区域尾部短块，引用总数有
500,000上限，原始块长总和必须等于文件长度。每块只存实际none/数值配方，解码
无需外部FITS解析器或源文件。分段读取器构建unsigned-64前缀数组并二分定位范围，
固定布局仍用算术定位。完整清单/块/文件SHA、受限解压、损坏拒绝和发布前校验保留。
v6不支持CSV、独立单元或Blosc；旧读取器拒绝v6。默认none/v2、数值/v4、Blosc/v5、
独立单元/v3、CAS1保持不变。base复用要求同v6布局与策略，复用前校验原始块。

持久性文字同步校正：归档写入执行flush/fsync；既有归档解包关闭恢复文件并在校验
后发布目录，未逐文件fsync。此前部分说明对此描述过强，本版明确区分。实测使用
上述相同语义，没有把未执行的恢复fsync算入成本，也不宣称掉电持久性。

## 预定协议与数据

规则、矩阵、验收于协议提交38473b2冻结；新文件事先仅检查头/尺寸，未测压缩率。
开发：已见Spitzer。验证：完整M13叠加float64图像11,586,240B、ROSAT float32图像
478,080B；源commit/每文件SHA固定。M13约145万个像素；ROSAT约22.66%正零。
两份均为同托管项目天文产品，不能称跨领域或严格盲测。另测既有ECG/噪声回退对照。
原始数据和用户研究文档不进入发行包；来源和署名见docs/DATASETS.md。

每组20条件：Zlib6/Zstd3 ×64KiB/1MiB ×普通固定/整文件重排/固定类型/仅分段/分段类型。
全部同v6，条件/轮次打乱，一次完整预热后五轮正式，新进程分阶段测wall/CPU/RSS。
范围五轮，两种读取器生命周期，同轮跨所有配置共享请求，实际样本/指纹全部保留。
前缀数组逻辑内存、完整归档、实际配方、专用源文件分别计量。layouts.py 3,393B、
numeric.py 1,431B，合计4,824B，按声明方法全额分配一次，即使未知格式回退也计费。
公共Python/core/Zstd与pyc未全额分配，不称完整部署成本；无新DLL/模型/字典。

预定联合验收：每个同codec/最大块长的分段类型候选，须同时相对普通固定与整文件
重排，在计源后成本不增，完整恢复、常驻p95、重开p95配对中位>=1且每项至少4/5轮
更快才通过。编码成本另列，不据此宣称综合支配。空间单项收益和失败均保留，未回调
规则或删除失败输入。最终数值见results/v0.12.0/SUMMARY.md与derived-metrics.json。

实测500次正式完整恢复、96,000次正式范围读取，另100次恢复预热、12,000次查询
预热全部逐字节一致。两个新验证记录的预定工作点 **0/8通过**，开发与回退对照也
保留全部失败。每方法各自最小归档，两份新输入专用源共用一次：普通2,921,262B；
整文件重排1,961,771+1,431B，净省32.796%；分段类型1,960,598+4,824B，净省32.720%。
分段归档仅少1,173B，新增layouts.py后反而多2,220B；没有超越已有整文件重排。
单组M13/ROSAT整文件重排净省35.70%/8.92%，分段类型35.56%/8.31%。仅分段合计
计源后增加0.121%。32.80%受新的大float64输入主导，不是相对v0.11的算法升级倍率。
未知ECG回退虽然精确，却错过已知int16变换的空间收益。默认保留原策略。
