# v0.19.0 · 原始QASPER字节适配与长历史边界

新增QASPER原始JSON成员定位和论文文本投影。每个locator直接指向原文件中的key、
冒号和值，保留UTF-8、转义、空白和原文件名；单个片段可恢复论文ID。只投影title、
abstract、full_text段落，qas问答标注、图表等不进FTS或模型证据句子。完整原文所有
字段仍在CAS。重复key/未知模式/截断拒绝；原有64MiB文件/1MiB记录限制不变。

**已知性能限制：25%变化门槛之前，增量查询可能严重慢于完整索引；本版保留并公布
该负结果，没有修改既有门槛。真实QASPER发布也未获得增量索引空间优势。**

## 兼容与使用

物理归档v1–v6/CAS1/记忆v1-v3不变；QASPER新来源kind=qasper-json-member-v1需要
v0.19解析，旧v0.18不能读该类型命中。旧文本/SciFact库仍兼容，没有自动迁移/GC。

```powershell
python -m rkv1 fetch data/qasper --dataset qasper
New-Item -ItemType Directory data/qasper-dev-source
Copy-Item data/qasper/qasper-dev-v0.3.json data/qasper-dev-source/
python -m rkv1 memory-init data/qasper-memory data/qasper-dev-source
python -m rkv1 memory-search data/qasper-memory "cross lingual transfer"
```

对需要稳定读取延迟、愿意每版保留完整索引的新库，可显式使用已测完整重建策略；
这是新建库选择，不迁移或覆盖已有库：

```powershell
python -c "from rkv1.memory import Memory; m=Memory.create('data/qasper-full-index', index_profile='compact-full-v2'); m.add('data/qasper-dev-source')"
```

正式复现需按version_data.py取回三次固定发布，及解压精确实测库/原native.json。
新输出目录/文件必须不存在，不覆盖旧结果：

```powershell
python -c "from rkv1.version_data import fetch_versions; fetch_versions('data/qasper-versions')"
python -m scripts.run_memory_history --out results/local-history --work .tools/local-history --native-library measured/rkv1_core.dll
python -m scripts.analyze_memory_history results/local-history --test-log path/to/test.log --native-library measured/rkv1_core.dll --plot
```

原始语料、问答原文、私有研究与密钥不发布。无E3、长期对话、多跳、跨域泛化、
冷缓存/跨机器、并发写入、目录/掉电持久性结论。下一步优先约束重放时间、分离
论文投影与原始路径/标注变化，再扩真正论文内容修订和更大独立问答。
