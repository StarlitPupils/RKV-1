# v0.16.0 · 紧凑基础索引与精确增量重放

修复v0.15记忆库中正文重复保存、每快照重建完整索引的成本问题。新建记忆库使用
contentless FTS5＋32B原记录SHA定位表；小幅更新仅保存压缩增量，查询时在内存中
重建完整当前视图，继续由SQLite全库BM25排序。每次查询保留基础/增量SHA和命中
CAS原记录校验；不按独立分片分数合并，不删历史快照制造空间收益。

## 实测结果

协议与46个Python模块在提交 `5126566` 冻结。相同SciFact原始语料、CAS、标签、
查询，三策略×三轮；4,275次正式查询、1,764次旧快照查询的key排序及来源身份均
匹配full-v1，BM25绝对误差<=1e-10。独立科学主张仍为188条。初始排名与v0.15一致，
gold文档宏平均召回@5仍为88.34%。无新模型调用，不报告新推理质量。

| 阶段 | 完整正文索引 | 紧凑完整索引，另计专用源 | 紧凑增量，另计专用源 | 增量相对旧策略净省 |
|---|---:|---:|---:|---:|
| 原始语料，一快照 | 19,319,447B | 8,430,886B | 8,430,887B | 56.36% |
| 追加88B，保留两快照 | 35,687,007B | 13,899,113B | 8,443,735B | 76.34% |
| 大幅定位移动，保留三快照 | 55,006,534B | 22,319,307B | 16,863,929B | 69.34% |
| 删除控制，保留四快照 | 74,320,531B | 30,733,971B | 25,278,593B | 65.99% |

完整专用memory_index.py 10,731B一次计入两个紧凑候选。公共Python/SQLite/core、
文件系统元数据未全额分配。新库初始计源仍为原文8,307,875B的1.015倍，尚无整个
记忆系统净压缩结论。与v0.15含24个回答的35.73MB正式库不直接计算配对节省。

| 追加场景 | 查询中位 / p95 | 新查询进程峰值RSS中位 | 完整提交中位 |
|---|---:|---:|---:|
| 完整正文索引 | 37.09 / 54.46ms | 48.35MiB | 666.44ms |
| 紧凑完整索引 | 16.82 / 24.55ms | 38.01MiB | 683.27ms |
| 紧凑增量 | 25.61 / 36.37ms | 46.76MiB | 298.37ms |

增量相对旧策略逐问题/轮配对查询加速中位1.393倍。比紧凑完整索引更省保留空间，
查询却更慢、峰值RSS更高；空间/延迟/内存分别报告，不称全流程支配。查询计时含
全SHA检查和重放，不含子进程启动；另列进程总耗时。RSS含整个查询进程及加载，
不是单条请求的内存增量。全部本机温缓存，冷缓存/跨机器未测。

单份基础索引16,355,328→5,455,872B；追加88B时新写索引仅234B。提交仍全量读取
并哈希来源、扫描记录。已有8层增量，或超过25%记录定位改变时完整建紧凑检查点，
并保留旧文件。改写/删除阶段为合成机制控制，不是新科学数据或推理改进。

## 兼容与验证

原v1应用记忆库可读写且继续原策略，无自动迁移。新v2应用清单需v0.16读取器，
v0.15会拒绝；归档v1–v6、CAS1、旧CLI命令和模型请求/引用协议保持不变。
原有12个检索条件模型请求的正文SHA及原响应引用在三策略三轮共核对108次，属于
离线兼容检查，无新生成。派生回答仍单独保存，不进入主证据索引。

本机141项测试：140通过、1项Windows符号链接权限跳过；覆盖增删改/偏移变化、
全库排序、旧快照、检查点、损坏拦截、发布失败及已验证孤儿重用。发行包另验
安装后记忆v1/v2、v0.15旧归档读取器及HTML资源；CI与实际资产核验随Release附加。
原始数据、用户研究文档和密钥不进入包。本轮E4成本改进；E3神经压缩、长期连续
对话、多跳和形式化验证仍未实现，目录/卷/真实掉电未验证。

本机另重建演示库，两个CAS快照ID和25条既有派生记录逐字节保留；文件总量
35,728,598→8,474,595B。这是独立机制核验，不是自动迁移工具或正式时序对照，
上述值不含另列的专用源码。演示未配置密钥，仅检索。

## 运行与复现

```powershell
python -m pip install -e .
# SOURCE是完整资料树，新建库默认紧凑增量索引。
python -m rkv1 memory-init data/new-memory data/memory-source
python -m rkv1 memory-search data/new-memory "rare genetic variants"
python -m rkv1 memory-add data/new-memory data/updated-source --label revision-2
python -m rkv1 memory-serve data/new-memory
python -m scripts.run_memory_index --out results/local-memory-index --work .tools/local-memory-index
python -m scripts.analyze_memory_index results/local-memory-index --test-log path/to/test.log --plot
```

模型配置沿用RKV_LLM_BASE_URL/MODEL/API_KEY环境变量，不保存密钥。正式索引实验不会
调用模型。Python API可用Memory.create(...,index_profile="compact-full-v2")选择按快照
完整重建的紧凑对照；所有策略保留原文/历史，不提供自动GC。
