# v0.22.0 · 批量校验重绑定并直接查询只读基础

v0.21的v4即使只有定位变化，每次查询仍复制SQLite并逐条校验/写定位。本版将全部
重绑定以每批256个key核对基础key/kind/投影SHA，并将已验证的新locator保存在
请求内映射；返回命中才替换定位。纯定位/位移overlay直接查询只读基础；FTS删除/
upsert仍复制数据库、完整重放，保持全库BM25。非命中重绑定也检查，缺失/指纹不符/
重复/操作交叉拒绝，保留位移校验。完整基础/overlay/源树、CAS stored/raw、原记录
及当前投影SHA继续验证；请求结束释放，无跨查询缓存或校验跳过。

**默认继续预算v3，v4仍显式候选。新v4更快但仍慢于同轮v3。**

## 冻结对照

49模块、协议和runner于659c354冻结，候选CI 40097638909通过。原样复用v0.21
round0六个完整保留库：官方QASPER三发布固定/Gear各v3/v4，合成160篇9状态v3/v4。
15状态×四方案×三轮，180新进程；每次1预热排除。无新提交、来源、索引、迁移
或GC。前三个方案读同一v4根，第四读同源同SID的原v3根：

* v021：实际发布wheel的49模块，SHA匹配v0.21实验；逐条应用定位并复制。
* lazy-copy：当前批量/命中投影，但存在overlay时强制复制；无overlay不人为复制。
* lazy-direct：当前v4默认查询路径，有普通删除/upsert操作时复制。
* budget-v3：当前读取器读原v0.21预算v3库，作为默认参考，非纯代码加速分母。

先前64题cProfile只作诊断，含工具扰动，不能当正式时序或相加嵌套累计时间。
正式wall/CPU含整个search与释放；输入、整树核验/历史诊断不混入正式query，进程
总时长另列。相同问题小文件供给所有worker，不重新加载整份官方JSON选题；因此
RSS不与v0.21历史不同输入方式直接相除。配对比值按同问题/轮后取中位。

## 使用、兼容与限制

原有v4库直接使用新读取器即可；新建库仍须显式选择：

```powershell
python -m rkv1 memory-init path/to/new-memory path/to/evidence --index-profile compact-projection-v4
```

物理归档v1–v6/CAS1、记忆清单v1/v2/v3/v4、writer预算和持久格式不改，无自动
迁移。旧v0.21能读当前新建v4，旧v0.20仍拒绝v4；发布安装检查额外核对同输入/
标签下新旧v4 writer整个持久树逐字节一致。默认预算v3及旧v1/v2策略保留。

本机温缓存；无真实正文修订、冷缓存/跨机器、E3、多跳、长期对话、新模型质量、
掉电、并发写入或GC结论。下一步转向独立真实论文正文修订，并继续记录索引成本
与读取代价。HTML未改，无新增模型配置。Release保留精确旧fixture生成库用于复建，
当前Windows/Linux原生功能库另列，不把新CI二进制解释为查询性能来源。原始科学
语料/问题原文/私有研究不发布，摘要只含身份/题目SHA和计时。
