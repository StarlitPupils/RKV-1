# Memory 默认写入与配置的统一锁

本页记录 v0.100 开发候选。已交付的 v0.99 及其验证证据见 [原报告](../results/v0.99.0/SUMMARY.md)。

## 使用范围

连续修订资料时，默认写入和索引重放预算配置需要使用同一把锁。否则，一个调用在显式作用域中更新资料时，另一个调用仍可从默认入口进入。

`Memory.add()` 和 `Memory.enable_replay_budget()` 在操作期间持有现有的非阻塞 `.writer.lock`。命令行的 `memory-add` 和 `memory-budget` 沿用这些方法。`memory-init` 先独占创建新目录，再通过受保护的 `add()` 写入首份资料。针对已有目录的初始化会失败。创建空目录和首次写入分属两个步骤，初始化中途失败可能留下目录。

需要连续执行多项操作时，可在 `with memory.writer() as scope:` 中调用 `scope.add()` 和 `scope.enable_replay_budget()`。两者共用当前作用域，避免再次取锁。其他默认写入遇到持锁者时立即返回 `BlockingIOError`，命令行沿用错误退出码 2。默认调用退出时释放作用域，显式调用由持有者关闭。

锁保护本版本支持的 Memory 更新和预算配置。旧版本、直接 Store 写入和外部文件改写仍需单独协调。锁释放与写入完成分别判断，原文核验、固定版本读取和历史定位沿用现有机制。

## 验证与交付条件

以 v0.99 的显式作用域为对照，新增检查只针对默认入口共锁。自建资料用于检查独立命令行进程的初始化、竞争拒绝、锁释放后的写入和配置，以及持锁期间文件身份和历史原文。错误调用还需验证作用域释放。这里的结果属于工程行为验证。

本地 Windows 全量回归使用隔离的 Python 环境和已有原生库，共 634 项，633 项通过，1 项因账户缺少符号链接权限跳过。新增的两项检查均通过。另比对了改动前后的写入和预算变更方法，公开参数及原操作逻辑一致。

另完成一轮固定 9 条自建记录的本地进程验收。父进程持有真实写入进程句柄，记录两次强制终止和一次正常退出。独立检查器复核保留的命令行输出、退出顺序和 18 次查询的原始 JSONL 字节、引用位置及历史版本。三组结果如下。

| 写入边界 | 进程退出后可见版本 | 原写入调用完成状态 |
| --- | --- | --- |
| 版本指针发布前终止 | 旧版本 | 未知 |
| 版本指针发布后终止 | 新版本 | 未知 |
| 放行发布并正常返回 | 新版本 | 已确认 |

持锁期间，6 次独立命令行更新或配置调用均退出 2，库文件身份前后一致。确认原进程退出后，3 次不同意图的更新和 3 次预算配置均成功。被终止的写入保留原记录。该轮为本地验收，正式验证方案仍待源码及 CI 冻结。

正式验证聚焦本次新增的竞争路径：

- 使用默认 API 的更新进程在版本指针发布前或发布后停在预定位置。另起真实 `python -m rkv1` 进程尝试写入和预算变更，记录退出码，并核对持锁期间原库身份。正常返回组从发布前的停点放行。用于观察边界的测试控制只放在更新进程内。
- 对中断场景，由父进程确认实际退出，再用命令行提交预先定义的另一份更新。独立核对当前和历史版本、固定读视图及原始资料。指针已发布但调用未返回的场景保留完成状态未知。
- 预先锁定规模、次数、故障边界、时间上限、原始记录和通过门槛。进程退出或记录缺失时保留原计划分母和已观测成本。正式验收聚焦本轮新增的默认入口，既有 v0.99 的结果继续作为历史证据。

[正式验收清单](memory-default-writer-plan.json)已固定用例顺序、输入指纹、预期状态和时间上限。17、129、513 条自建记录各跑 3 轮，每轮每规模覆盖上表三种边界。共 27 个独立库、27 个默认 API 写入进程、18 次受控终止、108 次独立命令行调用和 162 次来源查询。每例的命令行为两次竞争拒绝、两次退出后成功，查询为两个检查点各查当前、固定和显式旧版本。三项通过条件分别是完整退出与可见性记录、竞争期间无库变化且退出后独立更新成功、原文与历史引用独立核验通过。重复运行用于检验机制的一致性。正式执行器、源码提交和对应 CI 仍需一起核验。

## 执行与独立核验

执行器为 `scripts/run_default_writer_plan.py`，独立核验器为 `scripts/audit_default_writer_plan.py`，共同使用 `scripts/default_writer_plan.py` 检查清单结构和源码指纹。源码身份按 UTF-8 文本将 CRLF 规范为 LF，原始自建资料始终按实际字节核验。执行器只在外部提供对应提交 CI 和额度检查函数后接受正式模式。外部控制器应校验干净的源码提交、GitHub 实际 CI 运行的提交号及成功结论，并保存见证记录。

每例先独占创建新库和输出目录，保存开始预约与父进程实际退出记录。父进程在检查屏障、命令行调用和查询之间检查额度与截止时间。超时、子进程失败或身份不符时，保留已写记录和原计划分母，并清理属于本例的进程。后续人工检查缺失记录时，执行状态和额外资源成本保持未知。

本地自动化只用 9 条自建记录和三个场景，验证真实命令行、两次进程终止、原文核验及伪造退出记录拒绝。正式 27 例须在对应提交 CI 通过后另行执行。独立核验读取原始资料、命令行输出和退出凭据，检查时间顺序、库文件身份、当前及旧版本引用和完整源返回字节。完整父区间、成功子进程区间、自身 CPU 和峰值 RSS 分列，缺少子进程收尾记录时保留未知，全树 CPU 和 RSS 也保持未知。

接入执行器后的本地完整回归共 636 项，635 项通过，1 项因 Windows 账户缺少符号链接权限跳过，用时 122.965 秒。两项新增执行器检查覆盖小规模真实进程和退出篡改，以及计划顺序、输入、时间上限、分母、预期状态和源码集合的拒绝条件。

执行器第一次本地检查曾因超时变量遗漏中止，清理时又尝试终止已经退出的写入进程。现已修正变量和退出状态判断。失败测试临时目录被测试框架清理，该次临时原始记录及独立成本无法恢复，保留失败说明。先前独立本地验收的原始记录另存。

首个候选提交的 CI 在 Windows Python 3.10 的命令行凭据比较处失败，Linux 两个 Python 版本和两平台 Rust 检查通过，正式运行尚未启动。检查发现执行器解析了实际目录路径，而独立核验器仍沿用传入路径，等价路径写法会导致参数比较失败。核验器现统一解析目录路径，回归检查加入带 `..` 的等价路径。失败 CI 日志和停止状态保留，后续按修正提交重新验证。

公开交付前需完成回归、协议和输入冻结、对应提交的 CI、正式运行和独立核验，以及实际发布包的安装和产物核验。工程范围以覆盖这些写入入口为止，随后回到 [带版本修订的证据问答](DEVELOPMENT-GUIDE.md) 评测设计。
